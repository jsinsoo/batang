빅오 표기법은 실제 초 단위 실행 시간을 뜻하지 않습니다. 연산 횟수의 증가율을 나타내며 상수와 실행 환경에 따라 실측 시간은 달라질 수 있습니다.

1. 알고리즘 성능과 입력 크기 n

O(1)과 O(n)의 차이

첫 원소 접근은 입력 길이와 무관하게 한 번 수행합니다. 합계 계산은 모든 원소를 방문하므로 n번 반복합니다.

과정 출력 파이썬 코드

def first_value(data):
    print("첫 원소 접근: 인덱스 0 →", data[0])
    return data[0]

def total(data):
    s = 0
    for step, x in enumerate(data, 1):
        before = s
        s += x
        print(f"{step}회: {before} + {x} = {s}")
    return s

data = list(range(10))  # 출력 확인용; 원래 예제는 range(100)
print("첫 값:", first_value(data))
print("총합:", total(data))
print("입력 크기:", len(data))

실행 결과와 과정

첫 원소 접근: 인덱스 0 → 0
첫 값: 0
1회: 0 + 0 = 0
2회: 0 + 1 = 1
3회: 1 + 2 = 3
4회: 3 + 3 = 6
5회: 6 + 4 = 10
6회: 10 + 5 = 15
7회: 15 + 6 = 21
8회: 21 + 7 = 28
9회: 28 + 8 = 36
10회: 36 + 9 = 45
총합: 45
입력 크기: 10

해설: 첫 값: 0, 총합: 45, 방문 횟수: 10. 원래 range(100)의 합은 4950입니다.

2. 빅오 표기법

O(1)과 O(n)의 연산 횟수

상수 시간은 입력이 증가해도 주요 연산 횟수가 일정합니다. 선형 시간은 입력 크기에 비례해 증가합니다. 출력 자체가 많으면 출력 비용이 추가됩니다.

과정 출력 파이썬 코드

def constant_work(n):
    result = n * 2
    print(f"n={n}: 곱셈 1회 → {result}")
    return result

def linear_work(n):
    count = 0
    for i in range(n):
        count += 1
        print(f"{i+1}회 반복: count={count}")
    return count

print("상수 결과:", constant_work(10))
print("선형 결과:", linear_work(10))
# 원래 n=1000이면 각각 2000, 1000 출력

실행 결과와 과정

n=10: 곱셈 1회 → 20
상수 결과: 20
1회 반복: count=1
2회 반복: count=2
3회 반복: count=3
4회 반복: count=4
5회 반복: count=5
6회 반복: count=6
7회 반복: count=7
8회 반복: count=8
9회 반복: count=9
10회 반복: count=10
선형 결과: 10

해설: n=10일 때 상수 결과 20, 선형 결과 10. 원래 n=1000일 때 2000과 1000입니다.

3. O(log n): 이진 탐색

정렬된 배열의 탐색 구간 절반씩 줄이기

이진 탐색은 정렬된 자료에서만 올바르게 동작합니다. 가운데 원소를 비교하고 왼쪽 또는 오른쪽 절반을 버립니다. 최악 시간 복잡도는 O(log n)입니다.

과정 출력 파이썬 코드

def binary_search(a, target):
    left, right = 0, len(a) - 1
    step = 0
    while left <= right:
        step += 1
        mid = (left + right) // 2
        print(f"{step}회: 범위 [{left},{right}], 중간={mid}, 값={a[mid]}")
        if a[mid] == target:
            print("찾음! 비교 횟수:", step)
            return mid
        elif target < a[mid]:
            print("→ 오른쪽 절반 제외")
            right = mid - 1
        else:
            print("→ 왼쪽 절반 제외")
            left = mid + 1
    print("찾지 못함. 비교 횟수:", step)
    return -1

a = [2, 5, 8, 12, 16, 23, 38]
print("위치:", binary_search(a, 23))
print("없는 값:", binary_search(a, 7))

실행 결과와 과정

1회: 범위 [0,6], 중간=3, 값=12
→ 왼쪽 절반 제외
2회: 범위 [4,6], 중간=5, 값=23
찾음! 비교 횟수: 2
위치: 5
1회: 범위 [0,6], 중간=3, 값=12
→ 오른쪽 절반 제외
2회: 범위 [0,2], 중간=1, 값=5
→ 왼쪽 절반 제외
3회: 범위 [2,2], 중간=2, 값=8
→ 오른쪽 절반 제외
찾지 못함. 비교 횟수: 3
없는 값: -1

해설: 23 탐색: 인덱스 3(12) → 5(23), 결과 5. 7 탐색: 인덱스 3(12) → 1(5) → 2(8), 결과 -1.

4. O(n²): 중첩 반복문

두 반복문의 전체 쌍 세기

길이가 n인 배열에서 바깥쪽 반복문 n번마다 안쪽 반복문이 n번 실행되므로 총 n²번 수행합니다.

과정 출력 파이썬 코드

def count_pairs(data):
    count = 0
    for i in range(len(data)):
        print(f"바깥 반복 i={i}, 값={data[i]}")
        for j in range(len(data)):
            count += 1
            print(f"  ({i},{j}) = ({data[i]},{data[j]}), 누적={count}")
    return count

print("전체 쌍:", count_pairs([1, 2, 3, 4]))

실행 결과와 과정

바깥 반복 i=0, 값=1
  (0,0) = (1,1), 누적=1
  (0,1) = (1,2), 누적=2
  (0,2) = (1,3), 누적=3
  (0,3) = (1,4), 누적=4
바깥 반복 i=1, 값=2
  (1,0) = (2,1), 누적=5
  (1,1) = (2,2), 누적=6
  (1,2) = (2,3), 누적=7
  (1,3) = (2,4), 누적=8
바깥 반복 i=2, 값=3
  (2,0) = (3,1), 누적=9
  (2,1) = (3,2), 누적=10
  (2,2) = (3,3), 누적=11
  (2,3) = (3,4), 누적=12
바깥 반복 i=3, 값=4
  (3,0) = (4,1), 누적=13
  (3,1) = (4,2), 누적=14
  (3,2) = (4,3), 누적=15
  (3,3) = (4,4), 누적=16
전체 쌍: 16

해설: 4×4=16회. 입력 길이가 2배가 되면 주요 연산 횟수는 4배가 됩니다.

5. 실제 실행 시간 측정

time.perf_counter()로 비교

시간은 하드웨어, 운영체제, 실행 환경에 따라 달라집니다. 측정 시에는 반복문 안의 출력문을 제거해야 출력 비용이 결과를 왜곡하지 않습니다.

과정 출력 파이썬 코드

import time

def linear_sum(n, trace=False):
    s = 0
    for i in range(n):
        s += i
        if trace:
            print(f"i={i}, 누적 합={s}")
    return s

print("작은 입력 과정:")
print("합계:", linear_sum(6, trace=True))
print("큰 입력 시간 측정 (출력 제외):")
for n in [10000, 100000, 1000000]:
    start = time.perf_counter()
    result = linear_sum(n)
    elapsed = time.perf_counter() - start
    print(f"n={n:>8}, 합={result}, 시간={elapsed:.6f}초")

실행 결과와 과정

합계: 15
큰 입력 시간 측정 (출력 제외):

해설: n=6의 합은 15입니다. 시간 수치는 실행할 때마다 달라집니다.

6. 알고리즘 선택

선형 탐색과 이진 탐색의 비교

선형 탐색은 정렬되지 않은 배열에서도 사용할 수 있고 최악 O(n)입니다. 이진 탐색은 정렬된 배열이 필요하고 최악 O(log n)입니다. 정렬 비용과 탐색 횟수도 함께 고려해야 합니다.

과정 출력 파이썬 코드

def linear_search(a, target):
    for i, value in enumerate(a):
        print(f"선형 {i+1}회: a[{i}]={value}")
        if value == target:
            return i
    return -1

def binary_search(a, target):
    left, right = 0, len(a)-1
    step = 0
    while left <= right:
        step += 1
        mid = (left+right)//2
        print(f"이진 {step}회: [{left},{right}], a[{mid}]={a[mid]}")
        if a[mid] == target:
            return mid
        if target < a[mid]:
            right = mid-1
        else:
            left = mid+1
    return -1

data = [2, 5, 8, 12, 16, 23, 38]
print("선형 결과:", linear_search(data, 23))
print("이진 결과:", binary_search(data, 23))

실행 결과와 과정

선형 1회: a[0]=2
선형 2회: a[1]=5
선형 3회: a[2]=8
선형 4회: a[3]=12
선형 5회: a[4]=16
선형 6회: a[5]=23
선형 결과: 5
이진 1회: [0,6], a[3]=12
이진 2회: [4,6], a[5]=23
이진 결과: 5

해설: 선형 탐색은 6회 비교 후 인덱스 5, 이진 탐색은 2회 비교 후 인덱스 5를 반환합니다.

학습 정리

① 자료의 첫 원소 접근: O(1) ② 순차 합계와 선형 탐색: O(n) ③ 정렬된 자료의 이진 탐색: O(log n) ④ 병합 정렬: O(n log n) ⑤ 모든 순서쌍 순회: O(n²)

정확한 결과를 내는지 먼저 확인하고, 정렬 여부·입력 크기·반복 탐색 횟수·실측 시간을 함께 고려하여 알고리즘을 선택합니다.
