01 · 입력과 연산

개념 1. 알고리즘 성능과 입력 크기 n

입력 크기 n은 이 예제에서는 리스트의 원소 개수입니다. 같은 자료를 받더라도 첫 값만 읽는 작업과 모든 값을 더하는 작업의 연산 횟수는 다릅니다.

과정 출력 코드 

def first_value(data):
    if not data:
        raise ValueError("빈 리스트에는 첫 번째 값이 없습니다.")
    print(f"첫 값 읽기: data[0] = {data[0]} (원소 접근 1회)")
    return data[0]


def total(data):
    s = 0
    for step, x in enumerate(data, start=1):
        before = s
        s += x
        print(f"{step}단계: {before} + {x} = {s}")
    print(f"덧셈 횟수: {len(data)}회")
    return s


# 과정을 읽기 쉽도록 작은 입력부터 확인합니다.
data = list(range(5))
print("입력:", data, "n =", len(data))
print("첫 값 결과:", first_value(data))
print("합계 결과:", total(data))

# 원래 예제와 같은 n=100의 결과도 확인합니다.
large_data = list(range(100))
print("n=100의 첫 값:", first_value(large_data))
print("n=100의 합계:", sum(large_data))
print("직접 total로 더하면 덧셈 100회가 필요합니다.")

상세 해설

입력의 크기를 먼저 정의하기
여기서는 len(data)가 n입니다. 다른 문제에서는 문자열 길이, 정점 수, 행렬의 행·열 수 등이 입력 크기가 될 수 있습니다.

무엇을 세는가?
첫 값 읽기는 원소 접근 횟수, total은 s += x 실행 횟수를 셉니다. 모든 기계 명령을 정확히 세는 것이 아니라 입력에 따라 증가하는 대표 연산을 정합니다.

O(1)과 O(n)
파이썬 리스트의 인덱스 접근을 상수 시간으로 보면 first_value는 O(1), total은 모든 원소를 한 번씩 읽으므로 O(n)입니다. range를 리스트로 만드는 준비 시간은 이 함수들의 분석에서 제외합니다.

전제와 출력의 영향
첫 값은 비어 있지 않은 리스트에서만 정의됩니다. 과정 출력은 학습을 위한 장치이며 실제 성능 측정 코드에서는 제거해야 합니다. 마지막 sum도 모든 원소를 확인하는 선형 작업입니다.

02 · O(1) / O(n) / O(n log n)

개념 2. 빅오 표기법: 증가하는 정도

빅오는 입력이 커질 때 실행 비용의 증가를 나타내는 점근적 상한입니다. 아래에서는 간단한 정수 연산이 일정한 비용이라는 모형을 사용합니다.

과정 출력 코드 

def constant_work(n, trace=True):
    result = n * 2
    if trace:
        print(f"n={n}: 곱셈 1회 → 결과 {result}")
    return result


def linear_work(n, trace=True):
    count = 0
    for i in range(n):
        count += 1
        if trace:
            print(f"i={i}: 누적 연산 횟수 = {count}")
    return count


constant_work(5)
print("선형 작업 결과:", linear_work(5))
print("입력 크기별 대표 연산 횟수")
for n in [10, 100, 1000]:
    print(f"n={n}: 상수 작업 1회 / 선형 작업 {linear_work(n, False)}회")


# 보충: 병합 정렬의 분할과 병합 → O(n log n)
def merge_sort(a, depth=0):
    indent = "  " * depth
    print(f"{indent}분할 대상: {a}")
    if len(a) <= 1:
        return a[:]
    mid = len(a) // 2
    left = merge_sort(a[:mid], depth + 1)
    right = merge_sort(a[mid:], depth + 1)
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    print(f"{indent}병합: {left} + {right} → {merged}")
    return merged


print("병합 정렬 결과:", merge_sort([7, 2, 6, 1]))

상세 해설

결과의 크기 ≠ 연산 횟수
constant_work(1000)의 반환값은 2000이지만 곱셈은 한 번입니다. linear_work(1000)은 반복 본문을 1000번 실행합니다.

상수와 낮은 차수 생략
대표 연산 횟수가 3n + 2라면 성장의 주된 항을 기준으로 O(n)으로 표현합니다. 그러나 작은 입력의 실제 실행 시간에는 상수 계수도 영향을 줍니다.

왜 병합 정렬은 O(n log n)인가?
절반씩 분할하는 단계가 약 log₂n개이고 각 병합 단계에서 합쳐 처리하는 원소 수는 O(n)입니다. 따라서 전체 비용은 O(n log n)입니다. 이 구현의 리스트 복사도 같은 점근적 시간 범위에 포함되며, 최대 보조 공간은 O(n)입니다.

빅오는 정확한 초 단위 시간이 아니다
빅오 자체가 곧 최악의 경우라는 뜻은 아닙니다. 최선·평균·최악 중 어느 상황의 비용을 분석하는지 별도로 명시합니다. 이 자료에서는 주로 최악의 경우 증가율을 비교합니다. 임의 정밀도 정수의 자릿수까지 따지면 산술 비용 모형도 달라질 수 있습니다.

03 · 절반으로 줄이기

개념 3. O(log n): 이진 탐색의 범위 감소

이진 탐색은 오름차순으로 정렬된 자료에서 가운데 값과 비교하여 탐색 범위를 절반가량 버립니다. 원본의 중복 정의와 return -1def 연결 오류를 정리했습니다.

과정 출력 코드 

def binary_search(a, target):
    left, right = 0, len(a) - 1
    step = 0
    while left <= right:
        step += 1
        mid = (left + right) // 2
        print(f"{step}단계: left={left}, right={right}, "
              f"mid={mid}, 값={a[mid]}, 후보 수={right-left+1}")
        if a[mid] == target:
            print(f"발견! 인덱스 {mid}, 반복 {step}회")
            return mid
        elif target < a[mid]:
            print("목표가 더 작음 → 왼쪽 범위 선택")
            right = mid - 1
        else:
            print("목표가 더 큼 → 오른쪽 범위 선택")
            left = mid + 1
    print(f"탐색 종료: 없음, 반복 {step}회")
    return -1


data = [2, 5, 8, 12, 16, 23, 38]
print("23 찾기 결과:", binary_search(data, 23))
print("--- 없는 값 7 찾기 ---")
print("7 찾기 결과:", binary_search(data, 7))

2단계: left=0, right=2, mid=1, 값=5, 후보 수=3
목표가 더 큼 → 오른쪽 범위 선택
3단계: left=2, right=2, mid=2, 값=8, 후보 수=1
목표가 더 작음 → 왼쪽 범위 선택
탐색 종료: 없음, 반복 3회

상세 해설

유지하는 범위
left와 right는 아직 확인할 후보 구간의 양 끝 인덱스입니다. mid는 (left + right) // 2로 계산하며 인덱스는 0부터 시작합니다.

왜 ±1을 하는가?
가운데 값이 목표가 아니라는 사실을 이미 확인했으므로 mid 자체를 제외합니다. right = mid - 1 또는 left = mid + 1로 바꾸어 반복이 반드시 진행되게 합니다.

반복 횟수와 비교 횟수 구별
각 반복에서 가운데 원소 하나를 조사합니다. 비어 있지 않은 길이 n에 대해 최악의 반복 횟수는 floor(log₂n) + 1 이하입니다. 한 반복에서 ==와 <를 모두 검사할 수도 있으므로 원시 비교 연산의 총수와 반복 횟수는 구별해야 합니다.

적용 조건
정렬 여부를 함수가 자동 확인하지 않습니다. 정렬되지 않은 리스트에는 결과를 신뢰할 수 없습니다. 중복값이 있으면 일치하는 인덱스 하나를 반환하며 첫 번째 위치를 보장하지 않습니다. 빈 리스트는 바로 -1을 반환합니다.

04 · 모든 순서쌍

개념 4. O(n²): 중첩 반복문의 증가

두 반복문이 각각 n번씩 돌면 안쪽 본문은 n × n번 실행됩니다. 이 예제는 자기 자신과의 쌍과 순서가 뒤바뀐 쌍을 모두 셉니다.

과정 출력 코드 

def count_pairs(data, trace=True):
    count = 0
    for i in range(len(data)):
        for j in range(len(data)):
            count += 1
            if trace:
                print(f"i={i}, j={j}: ({data[i]}, {data[j]}) → 누적 {count}")
    return count


print("전체 순서쌍 수:", count_pairs([1, 2, 3, 4]))
print("입력 증가 비교")
for n in [2, 4, 8]:
    print(f"n={n}: {count_pairs(list(range(n)), False)}회")

상세 해설

4 × 4 = 16회
바깥쪽의 i가 하나 정해질 때마다 j는 0, 1, 2, 3을 모두 방문합니다. 이런 묶음이 4개이므로 총 16회입니다.

입력 2배 → 작업 4배
n=2, 4, 8일 때 본문 실행 횟수는 4, 16, 64회입니다. 입력이 두 배가 될 때 대표 연산 횟수는 네 배로 증가합니다.

서로 다른 두 원소만 고른다면?
j를 range(i + 1, len(data))로 바꾸면 중복 없는 인덱스 쌍을 셉니다. 개수는 n(n−1)/2로 줄지만 증가 차수는 여전히 O(n²)입니다.

중첩 모양만 보고 판단하지 않기
안쪽 반복문이 항상 고정된 3번만 실행되면 전체는 O(n)입니다. 반복문이 몇 겹인지보다 각 반복의 범위와 전체 실행 횟수를 확인해야 합니다.

05 · 측정과 해석

개념 5. 실제 실행 시간 측정: perf_counter

과정 출력용 함수와 측정 대상 함수를 분리합니다. 출력, 입력 생성, 워밍업은 측정 구간 밖에 두고 같은 작업을 여러 번 측정하여 중앙값을 비교합니다.

과정 출력 코드 

import time
import statistics


def linear_sum(n):
    s = 0
    for i in range(n):
        s += i
    return s


print("[준비] 작은 입력으로 워밍업")
linear_sum(1000)
repeats = 5
for n in [10000, 100000, 1000000]:
    durations = []
    print(f"\n[측정 시작] n={n}, {repeats}회 반복")
    for trial in range(1, repeats + 1):
        start = time.perf_counter()
        result = linear_sum(n)
        end = time.perf_counter()
        elapsed = end - start
        # 검증과 출력은 종료 시각 기록 이후에 실행합니다.
        assert result == n * (n - 1) // 2
        durations.append(elapsed)
        print(f"{trial}회: 합={result}, {elapsed:.6f}초")
    median = statistics.median(durations)
    print(f"중앙값: {median:.6f}초 / 원소당 {median/n:.9f}초")

개념 6. 알고리즘 선택: 정확성·복잡도·적용 조건

같은 정답을 반환하는지 먼저 확인하고, 자료의 정렬 여부와 탐색 횟수, 준비 비용을 따져 알고리즘을 선택합니다. 이 코드는 앞 절을 실행하지 않아도 단독 실행됩니다.

과정 출력 코드 

def linear_search(a, target):
    for i in range(len(a)):
        print(f"선형 탐색: 인덱스 {i}, 값 {a[i]}")
        if a[i] == target:
            return i
    return -1


def binary_search(a, target):
    left, right = 0, len(a) - 1
    while left <= right:
        mid = (left + right) // 2
        print(f"이진 탐색: 범위 [{left}, {right}], "
              f"중간 인덱스 {mid}, 값 {a[mid]}")
        if a[mid] == target:
            return mid
        elif target < a[mid]:
            right = mid - 1
        else:
            left = mid + 1
    return -1


data = [2, 5, 8, 12, 16, 23, 38]
target = 23
print("자료:", data)
linear_result = linear_search(data, target)
binary_result = binary_search(data, target)
print("선형 탐색 결과:", linear_result)
print("이진 탐색 결과:", binary_result)
assert linear_result == binary_result == 5

# 정렬은 원래 인덱스를 바꿀 수 있습니다.
original = [23, 2, 16, 5]
ordered = sorted(original)
print("정렬 전:", original)
print("정렬 후:", ordered)
print("정렬 전 23의 인덱스:", linear_search(original, 23))
print("정렬 후 23의 인덱스:", binary_search(ordered, 23))

상세 해설

먼저 정확성
두 함수는 이 예제에서 인덱스 5를 반환합니다. 선형 탐색은 최악 O(n), 이진 탐색은 정렬된 리스트에서 최악 O(log n)입니다. 두 방법 모두 운 좋게 첫 조사에서 발견하면 O(1)일 수 있습니다.

정렬되지 않은 자료를 한 번 찾기
선형 탐색은 바로 사용할 수 있습니다. 탐색 한 번을 위해 전체를 정렬하면 일반 비교 정렬 기준 O(n log n)의 준비 비용이 추가되므로, 이진 탐색이 무조건 유리하지 않습니다.

탐색을 q번 반복한다면
정렬되지 않은 자료를 선형 탐색으로 반복하면 최악 O(qn), 한 번 정렬한 뒤 이진 탐색하면 O(n log n + q log n)입니다. 입력이 자주 바뀌지 않고 탐색이 많을수록 후자가 유리할 가능성이 커집니다.

반환값의 의미와 추가 조건
정렬 후의 인덱스는 원래 인덱스와 다를 수 있습니다. 원래 위치가 필요하면 위치 정보를 함께 보관해야 합니다. 중복값에서 첫 위치가 필요한지, 메모리 제약이 있는지, 데이터 갱신이 잦은지도 선택 기준입니다.

확인 질문 해설

6개 질문의 답 확인
  1. n=8이면 첫 원소 접근은 1회, 합산의 덧셈은 8회입니다.
  2. 상수 작업은 1배, 선형 작업은 10배입니다.
  3. 가운데 값 12보다 목표 23이 크므로 오른쪽만 남깁니다. 다음 가운데 값 23에서 발견하므로 38은 확인하지 않습니다.
  4. 10,000개와 1,000,000개로 100배 차이입니다.
  5. 계산뿐 아니라 문자열 생성·출력 처리·입출력 대기 등이 섞여 알고리즘의 계산 성능 비교가 흐려집니다.
  6. 한 번이면 선형 탐색이 단순하고 정렬 준비 비용이 없습니다. 여러 번이면 한 번 정렬한 뒤 이진 탐색하는 전체 비용을 비교합니다. 원래 위치와 갱신 빈도도 고려해야 합니다.
